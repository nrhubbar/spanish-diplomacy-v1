# Map Package Specification (spec version 2)

A map package says how a scenario is drawn and how players interact with it. The engine never reads it; the renderer reads both the map and the scenario and joins them only through stable ids.

- Machine-readable schema: `src/main/scenarios/schema/map.schema.json`, generated from `mapSchema.ts`.
- Reference packages: `src/main/scenarios/spain-1936-07-31/map.json` (three relief layers, 16 SVG regions, two enclave shapes, 30 rivers, 25 water names; generated by `npm run maps:build`, see `assets/maps/ATTRIBUTION.md`) and `src/test/fixtures/scenarios/tiny-front/map.json` (flat, hand-drawn).

## Coordinate space

Every coordinate is in `viewBox` units, the same space as the SVG geometry and the relief layers. Packages are pre-registered to that space by their own build pipeline, so the renderer applies no projection. The camera zooms and pans this space; text, strokes, and icons are drawn at constant screen size, so they stay sharp at every zoom.

A package with relief should produce its geometry, relief images, and coordinates from one projection in one pipeline, so they agree by construction. The reference package uses a Lambert conformal conic in kilometres (x east, y south).

## Fields

| Field | Type | Meaning |
|---|---|---|
| `specVersion` | `2` | Spec version. Version 2 changes nothing else yet; sub-territory geometry is added by the map-provinces stream. |
| `id` | id | Map id. |
| `viewBox` | `{ x, y, width, height }` | The coordinate space. The camera never pans its center outside it. |
| `focus` | rectangle | Area framed when a game starts, clear of the details pane. |
| `background` | `#rrggbb` | Fill beyond the relief layers. With terrain, use the color the outermost layer fades into at its edges, so the seam is invisible. |
| `geometry.svg` | asset path | SVG whose elements are the territory regions. |
| `geometry.stripSelectors` | CSS selectors | Elements removed before use (metadata, legends). Scripts, `foreignObject`, styles, and event attributes are always removed. |
| `terrain.layers[]` | `{ image, bounds }` | Optional relief: baked images (lighting, tint, and coastline already in the pixels), coarsest first, each covering `bounds` in view box units with square texels. Later layers draw over earlier ones and may fade out at their edges through alpha, so a change of resolution has no seam; the renderer draws them unlit and mipmapped, and places the same images with CSS as the loading state and the no-WebGL fallback. Without `terrain`, regions are drawn as flat fills. |
| `regions` | `{ [svgElementId]: { territoryId } }` | Which SVG elements belong to which territory. Several regions may share one territory. Unlisted elements are inert context. |
| `territories[id].unitAnchor` | point | Where counters for units without a city stack. |
| `territories[id].label` | `{ x, y, tier }` | Territory label. `overview` labels always show; `detail` labels show from operational zoom. |
| `territories[id].shape` | `{ kind: "circle", x, y, r }` | Drawn and hit-tested for territories with no SVG region (small enclaves). Its rendered radius is at least 9 screen pixels. |
| `cities[id]` | `{ x, y, tier }` | City marker position and label tier. |
| `contextLabels[]` | `{ text, x, y }` | Labels for neutral land (neighbouring countries). |
| `rivers[]` | `{ id, name, rank, path, mouth?, labelPath? }` | Optional scenery with no rules effect. `rank` is `main` (drawn at every zoom) or `tributary` (from the operational zoom). `path` is the course on playable land, downstream; `mouth` is the final stretch into the sea, drawn tapering; `labelPath` is the curve the name follows, from the operational zoom. Defaults to none. |
| `waterLabels[]` | `{ text, tier, x, y }` or `{ text, tier, paths }` | Optional names of seas, gulfs, and bays: straight at a point, or along a curve. `tier` is `overview` (always shown), `operational` (from the operational zoom), or `detail` (from the detail zoom). A curved name lists `paths` in order of preference, and the renderer uses the first that fits on screen. Defaults to none. |
| `unitSymbols` | `{ [unitTypeId]: asset path }` | Counter symbol per unit type. An element with id `Friendly Fill` is recolored to the faction color. |
| `attribution[]` | `{ text, url? }` | Shown on the Settings screen. |

Paths (`path`, `mouth`, `labelPath`, `paths`) are open polylines in SVG path data: one or more `M x y` moves, each followed by relative `l` steps, with numbers separated by a space or run together before a minus sign. Label curves read west to east, or south to north when they are mostly vertical, so text is never upside down.

Text in a package may carry any Unicode; generated packages write characters outside ASCII as `\u` escapes.

Asset paths are repository-relative (`assets/maps/...`) `.svg`, `.png`, `.jpg`, or `.webp` files. Runtime map or tile services are not allowed; every asset is local.

## Validation rules (L10, L11)

- Every scenario territory has a map entry, and a bound SVG region or a `shape`.
- Every bound region exists as an element id in the SVG (checked when the SVG loads).
- Every region binds to a known territory; every map territory and city entry names a known id.
- Unit anchors and cities lie inside the `viewBox`.
- Every unit type has a symbol, and every named asset exists.
- River ids are unique, and every river and water-label point lies inside the `viewBox`.

## Rendering contract

- Territory fill is the controller's faction color at low opacity. Contested territories are striped in their contesting factions' colors, so control is never shown by color alone.
- Selection outlines (gold origin, dashed cyan legal destinations, white changed territories) are drawn above all regions.
- Counters are laid out in screen space at their city or territory anchor. A stack that would cover a label or another stack moves to a free slot beside or below it.
- Sea connections are drawn as dotted lanes between territory anchors.
- Layers, bottom first: territory wash, rivers, borders, highlights, sea lanes, water labels, context labels, territory labels, cities, routes. Rivers sit above the wash so they keep the water colour under every faction, and they take no pointer input.
- River strokes are fixed in screen pixels (about 2.4 px for main rivers and 1.4 px for tributaries) in the relief's shore-water colour with a paler centre line; a `mouth` narrows in steps toward the sea.
- Water labels are italic serif in deep sea blue on a pale halo. Open seas are capitals spread along their curve; gulfs and bays sit straight. River names run just above their river.
- Labels that name scenery yield instead of being cut or covered; panning or zooming brings them back. A context label is drawn only when it lies wholly on screen and touches no counter. A water or river label is drawn only when it lies wholly in the part of the screen the pane leaves free and touches no counter, territory or city label, or map control.
